# Translation pipeline (tools/)

These scripts re-harvest the UI dictionaries from an installed DeepSeek Harness
and regenerate `lib/client.js`. They exist so the pack can be updated when a
new DSH version changes interface strings.

> The scripts were developed against DSH `0.2.0-rc.2` on Windows.
> Paths at the top of each script are examples — adjust them to your machine.

## Files

| File | Role |
|---|---|
| `asar.ps1` | Lists/extracts files from the app's `resources/app.asar` (DSH ships its packages packed there). Run with `powershell -ExecutionPolicy Bypass -File asar.ps1 -Pattern '<regex>'` or `-Extract <path> -Out <file>`. |
| `harvest.cjs` | Executes every extracted `dsh-client-*/lib/client.js` bundle in a mocked module loader and captures all `ctx.locale.register(ns, { zh, en })` calls → `namespaces.json`. |
| `extract-dict.cjs` | Static fallback for bundles that fail dynamic harvest (resolves `const` object literals, incl. spreads, via `vm`). |
| `export-ru.cjs` | Reverse-extracts the `ru` dictionaries from a compiled `lib/client.js` back into `ru-chunk-*.json` (the versioned, editable translation source). |
| `generate-client.cjs` | Merges `ru-chunk-*.json` translations, validates coverage + `{placeholder}` parity against `namespaces.json`, and writes `lib/client.js`. |
| `ru-chunk-*.json` | Versioned translation source, split into chunks (one file per ~10 namespaces) so renames of individual keys stay reviewable in git. Generated by `export-ru.cjs`; consumed by `generate-client.cjs`. |
| `namespaces.json` | Snapshot of every built-in `{ namespace → { en, zh } }` dictionary from DSH `0.2.0-rc.2`. |

> `lib/client.js` is **generated** — never edit it by hand. Edit `ru-chunk-*.json`
> (or re-harvest `namespaces.json`) and regenerate. The scripts use the `.cjs`
> extension because the package is ESM (`"type": "module"`) and these tools use
> `require`/`__dirname`.

## Editing the translation

1. Edit the `ru` values in `ru-chunk-*.json`. Keys, namespaces and
   `{placeholder}` variables must match `namespaces.json` exactly.
2. `node tools/generate-client.cjs tools .` — validates everything and rewrites
   `lib/client.js`. A byte-identical round-trip (`git diff` shows only the
   header comment) guarantees the source and the bundle are in sync.

## Update workflow for a new DSH version

1. Extract all client bundles from the new `app.asar` into a folder, e.g.
   `powershell -ExecutionPolicy Bypass -File asar.ps1 -Pattern '/lib/client\.js$'`
   then `-Extract` each into `bundles/`.
2. `node tools/harvest.cjs <bundlesDir> namespaces.json` — fresh English source.
   Check the failure list; use `extract-dict.cjs` for bundles that resist
   dynamic execution.
3. Diff against the previous `namespaces.json` — new/changed keys are the
   translation delta.
4. Translate the delta into `ru-chunk-*.json` files (same
   `{ namespace: { key: "…" } }` shape).
5. `node tools/generate-client.cjs tools .` — validates and writes
   `lib/client.js`. `MISSING` / `PLACEHOLDER MISMATCH` lines fall back
   to English; fix them and re-run.
6. Bump `version` (and `engines.dsh` after testing), update the changelog.

## Translation rules used in this pack

- Keys and namespace names are never translated; `{placeholder}` variables are
  preserved byte-for-byte.
- Neutral tone («вы» implied); buttons and actions use the infinitive.
- Brand and protocol names stay untouched: DeepSeek, DSH, Cordis, pnpm, npm,
  GitHub, Markdown, JSON, YAML, API, URL, etc.
